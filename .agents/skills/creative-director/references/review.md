# Review and iteration

Engineering record fields: id, status, required, evidence_method, coverage, unknowns, environment and evidence paths. For not_applicable, give a rationale. Required unknown/fail blocks a completed stage; optional unknown remains visible. Waivers are for project style findings, not silent overrides of broken core tasks.

Visual dimensions (0–10): product fit, hierarchy/composition, coherence, motion meaning/continuity, distinctive moments. Report concrete evidence and a limitation for each. Unobserved motion is unscored. Scores guide discussion, not universal quality claims. Fix highest-impact task or readability problems before polish.

Classify every finding:
- Finding: what was observed, at which state/viewport.
- Interpretation: why it matters under this project's principles.
- Decision: fix, justified retain, or gather evidence; name owner and acceptance action.

For nonconvergence, diagnose whether the problem is mechanical, unclear direction, missing asset/evidence or budget conflict. Upgrade only the relevant observation. Stop when scoped core behaviors pass and remaining judgments are recorded. Ask the user only for an unresolved input/decision that cannot reasonably be inferred.

For a controlled pilot, preregister A ordinary prompt, B same prompt plus technical skills, C B plus direction workflow. Freeze model/settings, assets, device, time and QA allowance. Keep first and final outputs, costs and failures. Randomize anonymous evaluation where feasible and disclose reviewer involvement. Small samples report individual scores and effect sizes; do not claim general efficacy from five ratings. Use frame-time distributions with sampling environment, not a high-percentile FPS as a slow-frame floor. Lab interaction timing is not field INP.
